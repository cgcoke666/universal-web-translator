Building resilient web scrapers that survive layout changes

By Dana Whitfield · Updated March 14, 2026 · 9 min read

Every scraping pipeline eventually meets the same enemy: the page changes and the selectors silently stop matching. The failure is rarely loud. You get an empty list, a null field, or worse — a plausible looking value from the wrong element.

Treat the document as a signal to be understood, not as a container to be indexed. Structural heuristics age far better than hard-coded paths.

Why positional selectors break

A selector such as div > div:nth-child(3) > span encodes a layout that the site owner never promised to keep. When a promotion banner is inserted above the article, the whole chain shifts by one and every downstream field is wrong by one position. 

// Fragile
const title = document.querySelector('div:nth-child(3) > h1').textContent;

// Resilient
const title = document.querySelector('h1')?.textContent ?? '';

A more durable strategy

Score candidate elements by cheap, semantic signals: text density, the ratio of link text to total text, the presence of sentence punctuation, and how much of the element is hidden. The highest scoring subtree is almost always the real content.

Rule of thumb: a news article is roughly 70% prose and under 15% link text. A navigation menu is the exact opposite.

Comparison of approaches

Approach Survives redesign Effort per site
Hard-coded CSS path No Low until it breaks
Readability-style scoring Mostly None
Machine-learned extraction Yes High
